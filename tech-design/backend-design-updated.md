# Word King 后端技术设计文档

## 1. 技术栈

- **编程语言**: Java 21
- **框架**: Spring Boot 3.x
- **持久层框架**: MyBatis-Plus 3.x
- **数据库**: IBM DB2
- **构建工具**: Maven
- **注解库**: Lombok
- **日志框架**: Logback
- **API 文档**: Swagger/OpenAPI
- **安全框架**: Spring Security

## 2. 项目结构

后端项目采用典型的 Spring Boot 项目结构，包名为 `com.hotpot.wordking`。主要分为以下几个模块：

- config: 配置类，包括 MyBatis-Plus 配置、安全配置、跨域配置等
- controller: 控制层，处理 HTTP 请求和响应
- service: 业务逻辑层，处理业务逻辑
- mapper: 数据访问层，与数据库进行交互
- entity: 实体类，对应数据库表结构
- dto: 数据传输对象，用于前后端数据传输
- vo: 视图对象，用于数据展示
- exception: 异常处理类

## 3. 数据库设计

### 3.1 数据库表结构

#### 3.1.1 用户表 (T_USER)
用户表用于存储系统用户的基本信息，包含用户名、密码、邮箱、昵称等字段，并记录创建和更新时间。

#### 3.1.2 词汇表 (T_WORD)
词汇表用于存储词汇信息，包含词汇本身、音标、释义、词性、例句、难度等级和分类等字段。

#### 3.1.3 文章表 (T_ARTICLE)
文章表用于存储文章信息，包含标题、内容、摘要、作者、状态等字段，并记录创建和更新时间。

#### 3.1.4 练习会话表 (T_PRACTICE_SESSION)
练习会话表用于记录用户的练习会话，包括用户ID、词汇ID列表、题目总数、正确答案数、得分、开始和结束时间等。

#### 3.1.5 练习记录表 (T_PRACTICE_RECORD)
练习记录表用于记录每道题目的练习情况，包括会话ID、词汇ID、用户答案、是否正确、答题时间等。

## 4. 实体类设计 (Entity)

实体类对应数据库表结构，使用 Lombok 注解简化代码。使用 MyBatis-Plus 的注解标记表名和字段，并通过字段填充功能自动处理创建和更新时间。

Word 实体包含词汇的基本信息如词汇、音标、释义、词性、例句、难度等级等。
Article 实体包含文章的基本信息如标题、内容、摘要、作者、状态等。

## 5. 数据访问层 (Mapper)

数据访问层继承 MyBatis-Plus 的 BaseMapper，获得基本的增删改查功能。针对特定需求编写自定义查询方法，如根据难度和数量随机获取词汇、根据分类获取词汇、模糊搜索词汇等。

MyBatis-Plus 配置包括分页插件、自动填充处理器等，配置扫描 `com.hotpot.wordking.mapper` 包下的所有 Mapper 接口。

## 6. 业务逻辑层 (Service)

业务逻辑层实现具体的业务功能，包括词汇管理、文章管理、练习管理等。使用事务管理确保数据一致性。

WordService 提供词汇的增删改查、分页查询、练习用词汇获取等功能。
ArticleService 提供文章的增删改查、分类管理等功能。
PracticeService 提供练习会话管理、练习记录统计等功能。

## 7. 控制层 (Controller)

控制层定义 RESTful API 接口，处理 HTTP 请求并返回响应。使用统一的响应格式，确保前后端数据交互的一致性。

WordController 提供词汇相关的 API 接口，包括获取词汇列表、创建、更新、删除词汇等。
ArticleController 提供文章相关的 API 接口。
PracticeController 提供练习相关的 API 接口。

## 8. 配置文件

application.yml 配置文件包含服务器端口、数据源、MyBatis-Plus、日志等配置信息。数据源配置连接到 IBM DB2 数据库。

## 9. 统一响应格式

定义统一的响应格式 Result 类，包含状态码、消息和数据，便于前端处理响应结果。

## 10. 异常处理

实现全局异常处理器，统一处理参数验证异常、绑定异常和其他系统异常，返回友好的错误信息。

## 11. 安全性设计

使用 Spring Security 进行安全配置，包括禁用 CSRF、使用无状态会话、配置访问权限等。实现 JWT 认证机制，确保系统安全性。

## 12. 性能优化

配置缓存管理器，使用 Redis 作为缓存存储，提高系统性能。进行数据库优化，包括合理设计索引、使用连接池、SQL 优化等，避免 N+1 查询问题。
